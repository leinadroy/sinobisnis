# Smlgroupid

## Tech stack

Next.js (web, SEO) + NestJS (API) + Tailwind + shadcn/ui + Data Table (TanStack) + Prisma + MariaDB (production `sinobisnis` structure), all TypeScript. Details and conventions: `docs/tech-stack.md` — follow it for any new app code.

## Database (READ-ONLY)

- MariaDB 10.4 at 10.10.3.23 (needs VPN), database `sinobisnis`. Credentials in `.env` (not committed; template in `.env.example`).
- **This project only reads the database. Never write to it** — no INSERT/UPDATE/DELETE/DDL, not even "just to test".
- Always go through `tools/db.py` (`query()` in code, or `python tools/db.py "SELECT ..."` from the shell). It allows one SELECT/SHOW/DESCRIBE/EXPLAIN/WITH statement per call and locks the session READ ONLY. Do not open raw connections that bypass it.
- The `gxmysql` user has ALL PRIVILEGES on the server, so these guards are the only thing preventing writes.
- Exception approved by the user (2026-11-04): the new app's DB profile `production` (Developer Menu → Database) connects to production **read-only** — every pooled connection runs `SET SESSION TRANSACTION READ ONLY` + `max_statement_time = 120` (same as `tools/db.py`), the API's global `ReadOnlyGuard` rejects every non-GET request, reminders and menuitem sync are off, and login/roles come from the local DB (`DB_AUTH_PRODUCTION=local`). Credentials are referenced from the root `.env` via `DB_ENV_FILE`, not copied. Never set `DB_READONLY_PRODUCTION=0` or remove these guards outside an agreed go-live.
- **Currently OFF** — on 2026-11-10 the user asked again for production to be read-only for **all** tables, so `apps/api/.env` has `DB_WRITE_USERS_PRODUCTION=0` (no production password was changed while it was on). Turn it on only when the user asks again. What the flag does when on: optional second exception (approved by the user 2026-11-10): **only the `users` table** in production may be written, via `DB_WRITE_USERS_PRODUCTION=1` in `apps/api/.env`. Login, users and role access then come from production itself (not `DB_AUTH_PRODUCTION`), and a separate connection (`src/prisma/users-only.ts`, not session READ ONLY, `max_statement_time` 120) allows only `user.create`/`user.update` with plain column values — every other table, delete, upsert, `*Many` and raw SQL is rejected; the main connection stays READ ONLY and `ReadOnlyGuard` only lets `@AllowUsersWrite()` endpoints (Security → Users create/edit) plus the existing `@AllowOnReadOnly()` ones through. Passwords set this way are bcrypt, which the old GeneXus app cannot verify (user accepted). Bootstrap a login with `npm run user:password -- <username> --profile production` (the user runs it; never type their password). Do not widen this to other tables.
- `attachment` (~7.7 GB) and `invoiceattachment` (~2.3 GB) store file blobs. Never `SELECT *` from them; select the needed non-blob columns, and always use WHERE/LIMIT.

## Apps

- `apps/invoice-printer/` — self-contained Python/Tkinter desktop app (deliberately simple, not the Next.js/NestJS stack). Enter an invoice number or InvoiceId → `hasil/<InvoiceNo>/` with the invoice PDF, invoice+attachments merged PDF (bookmarked), and `attachments/` + `index.csv`. Has its own `.env` and its own copy of the read-only DB guard (`invoiceprint/db.py`) so the folder can be copied to another PC. See its README.
- Invoice layout is chosen by the invoice-number prefix: SML → `layout.py` (`build_sml`), RTS → `layout_rts.py`, JCSS → `layout_jcss.py` (modelled on `SML-/RTS-/JCSS-Invoice.pdf` in the project root); unknown prefixes fall back to SML. Typo fixes (`CORRECTIONS`) are in `layout.py`; DB → invoice mapping in `docs/invoice-mapping.md`.
- A few name lines in `invoicedetail` were saved with Qty > 0 but price 0 ("12. Zhu Yanhua"); `service.load` treats numbered zero-price lines as names. Zero-price service lines without a number are real and stay services.
- `apps/invoice-web/` — FastAPI web version for the office server (login, job queue, downloads incl. ZIP, auto-cleanup). Users in `data/users.json` via `manage_users.py` (not the sinobisnis `users` table). Its `invoiceprint/` and `assets/` are **copies** of the desktop app's — apply core/layout fixes to both. Local preview: `.claude/launch.json` → `invoice-web` on port 8000. See its README for deployment.
- `apps/api/` (NestJS 12 + Prisma 7.10.1 + `@prisma/adapter-mariadb`) and `apps/web/` (Next.js 16 + Tailwind + shadcn/ui base-nova + TanStack Table v8, port 3001) — the new Sinobisnis app that **fully replaces** the GeneXus app (no compatibility with it needed). Functional spec was the prototype in `C:\VibeCode\SinobisnisApps`. Setup, endpoints, business rules: `apps/api/README.md`.
  - **Database = production structure.** `prisma/schema.prisma` maps the GeneXus tables/columns as they are (`@map`/`@@map`). Never change the structure: no Prisma migrations, `prisma migrate diff` against the DB must be empty. Dev uses local XAMPP MariaDB `sinobisnis` (credentials: `LOCAL_DB_*` in root `.env`, `DATABASE_URL` in `apps/api/.env`), a clone of production made by `tools/migrate/clone_production.py all --replace` (reads production only via `tools/db.py`; blob columns left empty, so old attachments have no file content locally). Writing to the local clone is fine; production stays read-only.
  - GeneXus conventions: empty date = `1000-01-01`, empty text `''`, id 0 = none, placeholders "== Please Select ==" (company 0, bill to 0; hidden by name) hidden. DATETIME columns hold UTC (the old app stored UTC too — staff activity logs at 01:00–15:00), matching the adapter; `dt2s()` maps empty dates to null. DATE columns use `s2d`/`d2s`; "today" = `todayStr()` (server local date).
  - Passwords: legacy GeneXus hashes can't be verified; new passwords are bcrypt (`UsersSalt='bcrypt'`), set via Security → Users or `npm run user:password -- <username>` in `apps/api`. Access comes from `rolepgmname` per `MenuItemId`; menu ids 38–42 are added to `menuitem` at API start.
  - Invoices: `invoicedetail` qty > 0 = service line, qty 0 (or numbered zero-price) = TKA name; groups derived in `src/invoices/invoice-rows.ts`. Number = `CompanyInvoiceLastNo + 1` with GeneXus tokens, company row locked `FOR UPDATE`. Client ↔ invoice only via text `ClientNoInvoice`; `invoice.InvoiceNo` is not unique. Money rules (`computeInvoiceTotals`, `terbilang`, `formatInvoiceNo`) in `packages/shared/src/invoice.ts`. Print layout SML/RTS/JCSS by number prefix (`apps/web/app/print/invoices/[id]/layouts.tsx`); server PDF incl. merged attachments at `/bff/invoices/[id]/pdf[?attachments=1]` via headless Chrome/Edge (`PDF_BROWSER_PATH`).
  - Reminder: same rule as the old app (verified against legacy `datalog`): per Keperluan, only clients exactly on day N (0 = disabled), one email per category per Keperluan, templates by id 1–5, log text in `datalog` TableName `Reminder`. Pure rules in `apps/api/src/reminders/reminder.logic.ts`. Keep System Configurator `Reminder Enabled` off while the old app still sends reminders. **The local clone holds the real production SMTP settings and recipients** — point `SMTP Host` at a fake local server before testing a send.
  - Menu (`packages/shared/src/menu.ts`) mirrors the production menu at https://smlgroupid.com/sinobisnis (Data / Security / Account / Developer Menu); Email Reminder has no production menu entry and sits in Developer Menu.
  - DB profiles (Developer Menu → Database, Developer role only): connection URLs live only in `apps/api/.env` (`DB_PROFILES`, `DB_URL_<KEY>` may use `${DATABASE_URL}`, `DB_DATABASE_<KEY>`); the active choice is in `apps/api/config/db-profile.json`. `PrismaService` is a Proxy over the active client (internal fields start with `__` because `prisma.client` is the client table). Switching invalidates all JWTs (token carries `db`). Profiles: `local` = laptop `sinobisnis`; `staging` = shared server **10.10.3.62, MySQL 8.0.31**, db `sinobisnis_staging` (prod copy made 2026-11-05 with `clone_production.py all --target staging --replace --blob-latest 10`: full data; attachment tables partial with file content — 10 newest `attachment`, the 10 newest `invoiceattachment` widened to their whole invoices (2378 → 14 rows) plus every `attachment` they reference, so print-with-attachments works; refill only these with `clone_production.py blobs --target staging --blob-latest 10`; on 2026-11-05 all attachments of invoices dated 2026-10-01..2026-11-30 were added too (75 invoices, 966 rows, 430 MB) with `clone_production.py invoice-attachments --target staging --from 2026-10-01 --to 2026-11-30` — additive, re-runnable, verifies counts/bytes per invoice against production; credentials `STAGING_DB_*` in root `.env`; that server hosts many other databases — the clone script only ever drops/creates a name containing "staging"); `production` = 10.10.3.23 read-only (needs VPN). Staging users still have legacy hashes except `admin` (bcrypt copied from local). The laptop DB `sinobisnis_test` is no longer used. Read-only profiles: `prisma.authDb` serves login/users for AuthService; endpoints that must work there (login, password, DB switch/test) carry `@AllowOnReadOnly()`.
  - Deploy: Windows Server with IIS (URL Rewrite + ARR) → Next on 127.0.0.1:3001 → API on 127.0.0.1:4000 (`HOST`), both as NSSM services; guide `docs/deploy-windows.md`, scripts `scripts/deploy/`. Alternative: Docker on a Linux server (`docker-compose.yml`, `Dockerfile.api`, `Dockerfile.web` with Chromium, all in the repo root; DB stays external; `.env` files mounted read-only, never baked into images; guide `docs/deploy-docker.md`; built and tested 2026-11-05 on the laptop with Docker Desktop: login, lists, PDF+attachments against staging; npm in the images uses `legacy-peer-deps=true` because the lockfiles were made with that user npm setting). `COOKIE_SECURE=0` allows login over plain http for trials. Production build (`npm run build`) verified locally 2026-11-04. Stop the dev servers before `npm run build` locally (it rewrites `.next`/`dist`).
  - `packages/shared` (ESM) holds the menu, role-access defaults, `MASTER_ENTITIES` (drives the generic API master controller and web pages `/master/[entity]`), client/invoice/reminder types. Rebuild with `npm run build:shared` after edits.
